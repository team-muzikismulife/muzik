# 배포본 복원 계획

## 배경

공개 배포본(`https://dist-iota-six-90.vercel.app`)의 **소스가 저장소에 없다.**
원격 14개 브랜치와 로컬 클론 어디에도 없고, `scripts/deploy-web.mjs`가 `npx vercel deploy ./dist --prod`로
**빌드 산출물만** 올리는 CLI 배포라 Vercel에도 git 커밋·TypeScript 원본이 남지 않았다.

그래서 배포된 JS 번들을 역으로 읽어 동작을 특정하고, 이 브랜치에 다시 구현한다.

## 배포본의 정체 (번들 지문으로 확정)

`demo/spark-web`(c13b952)이 본체다. 근거:

| 지문 | 배포본 | `demo/spark-web` | `dev` |
|---|---|---|---|
| 데이터 레이어 | `subscribeRoom`·`subscribeTracks`·`subscribeMembers` | 같음 | `subscribeRoomHome`(다름) |
| 쓰기 경로 | `runTransaction` 클라 직접 | 같음 | 없음 |
| `DAY_CUTOFF_HOUR` | `0` | `0` | `4` |
| Firebase | `muzik-42b60` | 같음 | 에뮬레이터 |

여기에 **저장소 어디에도 없는 두 가지**가 얹혀 있다.

1. **공동 플리** — `dev`의 #37과 **다른 기능**이다. #37은 방 전체 트랙을 자동으로 모아 보여주는
   읽기 전용 큐였고, 배포본은 사용자가 곡을 담아 만드는 **다중 플레이리스트**다.
   문자열부터 갈린다: #37에는 "공동 플리에 담기"·"공동 플리를 만들었어요"가 없다.
2. **목업 프리뷰 룸** — 로그인·실데이터 없이 홈 화면을 보여주는 데모용 가짜 방.

## 목표

배포본과 같은 화면·같은 데이터 모델을 이 브랜치에서 재현한다. 이후 작업은 여기서 이어간다.

## 범위

- `demo/spark-web`의 기존 동작(곡 등록·수정·삭제, 초대, 검색)은 **손대지 않는다.**
- `dev`의 #33·#35·#37은 가져오지 않는다. 배포본에 없다.
- Cloud Functions 전환(정본 아키텍처)은 이번 범위가 아니다. Spark 저하 모드를 유지한다.

## 구현

### 1. 공동 플리 — 데이터 모델

번들에서 복원한 Firestore 스키마.

```
rooms/{roomId}/sharedPlaylists/{playlistId}
  { id, name, createdBy, createdAt, updatedAt, trackCount, coverVideoId? }

rooms/{roomId}/sharedPlaylists/{playlistId}/items/{videoId}
  { videoId, title, artist, sourceDateKey,
    recommendedByUid, recommendedByNickname, addedByUid, addedAt, order }
```

- 아이템 **문서 ID가 `videoId`** — 같은 곡을 두 번 담아도 중복되지 않는다(멱등).
- 기본 플레이리스트: ID `favorites`, 이름 `즐겨찾는 노래`.

### 2. `src/lib/api.ts`

- `ensureSharedPlaylist({ roomId, name })` — 없으면 생성, 있으면 이름·`updatedAt`만 갱신.
- `addTracksToSharedPlaylist({ roomId, tracks, playlistId, playlistName })`
  - `unavailable` 곡 제외 → `videoId` 기준 중복 제거 → 담을 게 없으면 `failed-precondition`.
  - 트랜잭션에서 **이미 있는 아이템은 건너뛰고** 새로 담긴 개수(`addedCount`)만 센다.
  - 플리 문서의 `trackCount`를 증가분만큼 올리고 `coverVideoId`가 비어 있으면 채운다.

### 3. `src/lib/db.ts`

- `subscribeSharedPlaylists(roomId, …)` — `updatedAt desc`.
- `subscribeSharedPlaylistItems(roomId, playlistId, …)` — `order asc`.

### 4. `app/room/[id]/shared-playlist.tsx`

- 플레이리스트 목록 구독 → 선택된 플리의 아이템 구독(2단 구독).
- 헤더 `+` 버튼 = `ensureSharedPlaylist` ("즐겨찾는 노래 폴더 만들기").
- 유튜브 핸드오프(`watch_videos`) + 인앱 미리듣기.
- loading / empty / error / ready 4상태.

### 5. `app/room/[id]/playlist/[dateKey].tsx`

- 하단에 **"공동 플리에 담기"** 추가 → `addTracksToSharedPlaylist`.
- 토스트: `{n}곡을 공동 플리에 담았어요` / `이미 모두 담겨 있어요` / `공동 플리에 담을 수 있는 곡이 없어요`.

### 6. 목업 프리뷰

- `src/lib/mockPreview.ts` — `MOCK_ROOM_ID = 'mock-preview-room'`, 멤버 4명(승완·보규·규호·수윤),
  오늘 기준 5일치 트랙, `getMockRoomState()` / `getMockTeamSummary()` / `isMockRoomId()`.
- `isMockPreviewEnabled()` — `EXPO_PUBLIC_MOCK_PREVIEW`가 `1|true|yes`일 때만 켠다.
- `src/store/teams.ts` — 목업이 켜져 있으면 팀 목록 맨 앞에 목업 팀을 끼우고,
  **실패해도 목업 팀 하나로 `ready`** 처리한다(로그인 없이 열람 가능해야 한다).
- `src/store/room.ts` — `isMockRoomId(roomId)`면 Firestore를 구독하지 않고 목업 상태를 넣는다.

> **배포본의 버그**: 홈은 목업으로 그리는데 공동 플리 화면은 실 Firestore를 읽으러 가서
> 목업 룸에서 `권한이 없어요`로 깨진다. 복원본은 공동 플리도 목업 분기를 태워 이 버그를 고친다.

### 7. `firestore.rules`

`sharedPlaylists`와 그 `items`에 대해 **멤버만** 읽기·쓰기. 삭제는 막는다(MVP 범위 밖).

## 확인

- `npm run lint`
- `node scripts/deploy-web.mjs --build` — 웹 빌드가 깨지지 않는지
- 목업 룸에서 홈 → 공동 플리 진입 → 4상태 확인
- 날짜별 상세 → 공동 플리에 담기 → 중복 담기 시 `이미 모두 담겨 있어요`

# 품질 점검 기록

## 2026-08-30 1차 점검

### 우선 수정 대상

1. 방 홈이 실제 방 데이터가 아니라 목업 팀명/멤버/곡을 보여줌
   - 영향: 팀 생성 또는 초대 입장 성공 후에도 사용자가 만든 팀과 다른 화면이 떠 M1 흐름을 신뢰할 수 없음.
   - 수정: `rooms/{roomId}`, `members`, 당일 `tracks`, `days/{dateKey}`를 포커스 중 실시간 구독하는 `room` store를 추가하고 방 홈을 연결.

2. 당일 곡 구독에 필요한 Firestore 인덱스 누락
   - 영향: `tracks`를 `dateKey`로 필터링하고 `order`로 정렬하는 홈 구독이 운영 Firestore에서 실패할 수 있음.
   - 수정: `firestore.indexes.json`에 `tracks(dateKey ASC, order ASC)` 컬렉션 스코프 복합 인덱스 추가.

3. 폼 검증값과 클라이언트 저장값 불일치
   - 영향: 서버는 zod `.trim()` 결과를 저장하지만 클라이언트의 최근 닉네임/공유 문구에는 앞뒤 공백이 남을 수 있음.
   - 수정: 팀 생성/초대 입장 submit 시 스키마 parse 결과를 API 입력과 로컬 저장에 사용.

### 남은 주요 리스크

- 날짜별 플레이리스트 상세 화면은 아직 목업 데이터를 사용한다. 다음 작업인 "날짜 다음페이지 수정"에서 실제 `dateKey`별 데이터로 교체해야 한다.
- 곡 등록 Functions와 등록 모달이 아직 없어 홈의 "곡 추가하기"는 준비 중 토스트만 띄운다.
- npm audit 기준 루트/Functions 의존성 취약점 경고가 있다. 기능 작업과 분리해 의존성 업데이트 이슈로 다루는 것이 안전하다.
